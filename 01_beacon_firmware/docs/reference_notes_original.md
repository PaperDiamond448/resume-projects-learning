## 〇、先建立几个基本概念（看不懂下面内容时回来查）

| 术语 | 大白话解释 |
|---|---|
| **单片机 / MCU / STM32** | 一块"很小的电脑芯片"，没有屏幕和键盘，专门用来控制硬件。这台设备的大脑就是一颗 STM32F427 芯片。 |
| **固件 (Firmware)** | 烧录进单片机里的程序。就是这个项目的全部 `.c` 代码编译出来的东西。它一上电就自动运行，不像手机App要点一下。 |
| **FPGA** | 另一块芯片，可以理解成"可以自定义的硬件电路"。它擅长做**极其精确的时间控制**（精确到百万分之一秒），这是单片机软件做不到的。本设备里它负责真正产生声波信号。 |
| **声呐 / 换能器** | "水下喇叭+麦克风"。换能器能把电信号变成水里的声波（发射），也能把声波变回电信号（接收）。本设备只用它来**发射**。 |
| **中断 (Interrupt)** | 单片机的"插队机制"。正常它在循环干活，一旦有紧急事件（比如收到一个字节、时间到了），会立刻暂停手头的事去处理，处理完再回来。下面会反复出现这个词。 |
| **串口 / UART / USART** | 两个设备之间用几根线收发数据的最常见方式。这台设备用串口跟岸上/船上的电脑（上位机）通信。 |
| **上位机** | 指挥这台设备的那台电脑（船上的控制软件）。它通过串口发指令过来，设备照做并回报。 |
| **RTC** | 实时时钟，就是芯片里的"电子表"，能记住年月日时分秒，还能"定闹钟"——时间一到就触发一次中断。 |
| **PPS** | 每秒一个的精确脉冲信号（Pulse Per Second），用来让多台设备的时间**对齐到同一秒**。水下定位对时间精度要求极高，所以需要它。 |
| **FMC** | 单片机和 FPGA 之间的一种"高速并行数据通道"，可以把 FPGA 当成一块内存来读写。单片机就是通过它给 FPGA 下命令的。 |

## 一、这台设备到底是什么？

它是 **"海底沉管高精度声呐测控系统"** 里的一个零件，叫 **"发射型水下声学信标"**，可以理解成一个 **"水下的精确发声器"**。

### 它在整个大工程里的位置

海底隧道是用一节一节巨大的混凝土管子（"沉管"，一节几万吨）在水下拼接而成的。把一节管子精确地沉到水底、和上一节对齐拼好，需要知道**这节管子此刻在水下的精确位置**（要求误差小到 3 厘米 / 100 米）。

办法是：
1. 在**管节上**装几个"发声器"（**就是这台设备**），让它们往水里发出声波脉冲。
2. 在**船底**装一排"接收器"，收这些声波。
3. 声波从管节传到船底各个接收器的时间有微小差别，**根据时间差就能反算出管节的位置**（这套算法叫 TDOA 差分定位）。

```
        船 ━━━━━━━━━━━━━━━━━━━  (船底装着一排"接收器")
        ╱│╲   ← 声波传到每个接收器的时间略有不同
       ╱ │ ╲
      ╱  │  ╲
   ┌─●───●──┐  ← 沉管管节，●就是本设备(发声器/信标)
   │  管 节  │
   └─────────┘
```

### ⚠️ 一个重要的事实：这台设备只负责"发声"

**这份固件只做发射端的工作**——准时发声、测自己在水下多深、跟上位机汇报状态。
那些高大上的部分（用时间差算位置、运动补偿、声呐和光学融合、画三维姿态图）**统统不在这份代码里**，它们在船上的接收设备和上位机软件里。

> 所以你舍友说"这程序只完成了项目的一部分"——是对的。**这部分就是整个系统的"发射端 + 数据采集底座"。**

## 二、设备内部是怎么连起来的（硬件接线）

核心要记住一句话：**单片机是"指挥"，FPGA 是"喇叭手"。**

单片机自己不直接发声，因为发声要求的时间精度太高（微秒级），软件做不到那么稳。所以单片机把"用什么频率、发多宽的脉冲、什么节奏发"这些参数通过 FMC 通道写给 FPGA，由 FPGA 这个"硬件电路"去精确地产生声波。FPGA 每发完一次，会戳一下单片机说"我发好了"。

```
                  ┌──────────────────────────────────────────┐
                  │           STM32F427  (单片机 / 大脑)       │
                  │                                            │
  船上电脑(上位机)─┤ 串口2 USART2(115200)  收指令 / 回报状态    │
  调试用电脑 ──────┤ 串口6 USART6(57600)   打印运行日志         │
                  │                                            │
                  │ FMC并行通道 ───────────────┐               │
                  │ (把FPGA当内存读写)          ▼               │
                  │                       ┌─────────┐          │
                  │ PA0引脚 ◄─────────────┤  FPGA   │          │
                  │  (FPGA说"我发完了"的中断)│ 产生波形 │         │
                  │                       └────┬────┘          │
                  │                            │              │
                  │ I2C ── MS5837 ◄─┐          ▼              │
                  │       (深度/温度  │     功率放大器          │
                  │        传感器)    │          │             │
                  │ ADC ── 测电池电压 │          ▼             │
                  │ GPIO ─ RGB 状态灯 │      换能器(水下喇叭)    │
                  │ RTC + PPS ── 控制"什么时候发声、时间对齐"     │
                  └──────────────────────────────────────────┘
```

各根线的作用：
- **串口2 → 上位机**：船上软件发指令（"开始发声""设置参数"），设备照做并回报。
- **串口6 → 调试**：开发时插一根线到电脑，能看到设备打印的运行日志，方便排错。
- **FMC → FPGA**：单片机给 FPGA 下发声参数的"高速通道"。
- **PA0 ← FPGA**：FPGA 发完一次声，拉一下这根线（产生"中断"）通知单片机。
- **I2C → MS5837**：一个深度/压力传感器，告诉设备"我现在在水下多深"。
- **ADC → 电池**：监测电池还有多少电。
- **GPIO → RGB灯**：红/绿/蓝指示灯，靠灯的颜色就能看出设备状态。
- **RTC + PPS**：电子表 + 每秒对齐脉冲，决定"什么时候发声"，保证多台设备时间一致。

## 三、开机后正常情况下会发生什么？（你能观察到的现象）

如果一切正常，**给设备上电后**会依次发生：

### 第 1 步：初始化（约 1~2 秒，悄悄进行）
单片机按固定顺序把自己准备好：先设好时钟频率 → 初始化内存 → 配好各个引脚 → 打开串口 → 启动电子表(RTC)。
- **现象**：调试串口(USART6)会打印出类似
  ```
  Hardware initialize over.
  System core clock is : 128M.
  ```
  这表示硬件底座就绪、主频跑在 128MHz。

### 第 2 步：加载参数 + 设备就绪
从芯片内部 Flash 里读出上次保存的配置参数（发声频率、增益等），然后打开中断系统，正式开始工作。
- **现象**：调试串口会继续打印设备信息（设备ID、地址、版本等）。代码里有一行 `SetArmLedR(false)` 把红灯关掉，表示"初始化阶段结束"。

### 第 3 步：进入待命主循环（一直循环）
此后单片机进入一个永远的循环 `while(1)`，但这个循环其实**很闲**，它只做三件不紧急的小事：
1. 刷新 LED 灯的闪烁；
2. 检查有没有"强制重载参数/保存参数"之类的请求；
3. 统计自己有多空闲（CPU 占用率）。

**真正重要的活儿都不在这个循环里，而是在"中断"里**（见下一节）。

### 第 4 步：每秒一次的"心跳"
电子表(RTC)每秒触发一次中断，设备借这个机会：
- 读一次深度传感器(MS5837)，看自己在水下多深；
- **根据深度让灯变色**：如果检测到已经入水（深度 > 0.2 米），**绿灯**闪；否则**红灯**闪。
  > 所以现场最直观的判断：**绿灯闪 = 设备已经在水里且工作正常；红灯闪 = 还在空气中/没入水。**
- 喂一次"看门狗"（防止程序卡死的保护机制）。

### 第 5 步：收到上位机指令时
当船上软件通过串口2发来指令，设备会立刻（中断）接收、解析、执行，然后回一条应答。比如收到"开始发声"指令，它就会把发声参数写给 FPGA，让 FPGA 开始按节奏发射声脉冲。

### 第 6 步：持续发声 + 上报
正常作业时，FPGA 按配置不断发射超短声脉冲，每发完一次通过 PA0 通知单片机；单片机同时持续把自己的深度、状态等通过串口上报给上位机。

> **一句话总结正常现象**：上电后调试口打印初始化日志 → 灯开始按状态闪烁（入水后变绿灯）→ 能响应上位机指令 → FPGA 持续发声、设备持续上报。

## 四、内部到底怎么运作的？（核心：中断驱动）

这是理解整个程序最关键的一点：

> **主循环很闲，真正的工作几乎全部由"中断"触发完成。**

打个比方：单片机像个前台，平时（主循环）就擦擦桌子（刷LED）。但只要电话响了（中断），它立刻放下抹布去接电话办事，办完再回来擦桌子。这台设备有三种最重要的"电话"：

### 链路①：上位机发来指令 → 执行
```
船上软件通过串口发来数据
      ↓ (串口中断响了)
USART2_IRQHandler          ← 一个字节一个字节地收  [stm32f4xx_it.c]
      ↓
Comm_GetFrameMsg()         ← 把零散字节攒成"一条完整指令"  [Comm_operate.c]
      ↓
OnEchoPCLINK()             ← 一个巨大的"分类台"，看是什么指令  [main.c]
      ↓
PCLINK_Decode_XXX()        ← 解析这条指令的具体内容  [PCLink_operate.c]
      ↓
Device_Decode_XXX()        ← 真正去改参数 / 给FPGA下命令  [iSBL_operate.c → iBeaconB_operate.c]
```
**作用**：让设备听从上位机指挥（开始/停止发声、改频率、改增益、对时间等）。

### 链路②：定时发声 / 时间同步
```
电子表(RTC)每秒闹钟响
      ↓ (RTC中断)
OnEchoRTC()                ← 算CPU占用率、喂看门狗  [main.c]
      ↓
Device_OnEchoRtc()         ← 转发给具体设备  [iSBL_operate.c]
      ↓
iBeacon_OnEchoRtc()        ← 读深度传感器，按深度切换红/绿灯  [iBeaconB_operate.c]

另外，每秒的 PPS 对齐脉冲到来时：
Device_OnEchoPps()         ← 到点了，置上"该发射"的标志  [iSBL_operate.c]
```
**作用**：保证设备"准时"发声，并让多台设备时间对齐（水下定位的命根子）。

### 链路③：FPGA 发声完成的反馈
```
FPGA 发完一次声，拉高 PA0 引脚
      ↓ (外部中断 EXTI0)
EXTI0_IRQHandler           ← [stm32f4xx_it.c]
      ↓
Device_OnEchoInt()         ← [iSBL_operate.c]
      ↓
FPGA_AcqProc()             ← 读FPGA状态、处理这次发声事件  [FPGA_operate.c]
```
**作用**：让单片机知道 FPGA 的发声进度，做相应的收尾处理。

> ⚠️ 注意：**真正"产生声波波形"这件事发生在 FPGA 内部的硬件电路里，不在这份 C 代码里。** 这份代码只负责"告诉 FPGA 该怎么发"以及"处理 FPGA 发完后的反馈"。

## 五、每个代码文件是干什么的？

> 提示：这套源码是"一套代码编多种设备"的设计——改一个宏(`DEVICE_SUBTYPE`)就能编译成信标、接收机、定位器等不同产品。
> 所以你会看到大量 `#if DEVICE_TYPE == ...` 的分支，**当前编译成"B型信标"时，里面很多分支是被直接删掉、不参与运行的**（详见第六节）。

### 🟢 核心业务（设备的"大脑"，最该读）
| 文件 | 干什么 |
|---|---|
| `main.c` | 程序入口、主循环、所有回调函数的总集散地。从这里开始读最合适。 |
| `iSBL_operate.c` | **设备分发层**。所有 `Device_xxx()` 函数在这——它像个总机，按设备型号把调用转接给具体实现。 |
| `iBeaconB_operate.c` | **当前这台"B型信标"的具体实现**。配置 FPGA 发声参数、读深度、响应RTC都在这。 |
| `PCLink_operate.c` | **跟上位机通信的协议**（3000多行）。指令解析(`Decode_*`)、回复(`Echo_*`)、参数存取(`SysParam_*`)。**按需查，别通读。** |

### 🟢 硬件驱动（设备的"手脚"）
| 文件 | 干什么 |
|---|---|
| `hw_config.c` | 配置主频时钟、编排开机初始化顺序(`Init_All_Periph`)。 |
| `Nvic.c` | 配置各个中断的优先级（谁能打断谁）。 |
| `stm32f4xx_it.c` | 所有中断处理函数(ISR)的集中地。 |
| `FPGA_operate.c` | **跟 FPGA 打交道**：通过FMC读写、配置发声波形、处理发声中断。本设备的关键文件。 |
| `Comm_operate.c` | 串口底层 + 把零散字节攒成完整一帧。 |
| `ms5837.c` | **深度/压力/温度传感器**驱动，测自己在水下多深。 |
| `IO_operate.c` | RGB 状态灯的控制逻辑（红/绿/蓝闪烁）。 |
| `ADC_operate.c` | 模数转换，主要用来测电池电压。 |
| `RTC_operate.c` | 实时时钟（电子表），发声定时和对时靠它。 |
| `Timer.c` | 定时器配置。 |
| `SPI_operate.c` | SPI 总线驱动（一种芯片间通信方式），底层备用。 |
| `Gpio.c` | 引脚配置的封装小工具。 |
| `malloc.c` | 自己实现的内存分配管理。 |
| `flash_if.c` | 读写单片机内部 Flash，**用来保存设备参数**（因为这版没插SD卡）。 |
| `aes.c` | AES 数据加密（可选功能，看开关）。 |

### 🟡 辅助工具（在用，但不是重点）
| 文件 | 干什么 |
|---|---|
| `sys.c` | 正点原子(ALIENTEK)开发板的系统辅助函数。 |
| `calendar.c` | 农历/公历换算表。 |
| `date.c` | 日期时间换算（时间戳 ↔ 年月日）。 |

## 五·补、一个容易踩的误区：用到的文件 ≠ 只有那三条链路

看完第四节的三条中断链路，很容易误以为"那只有这三条链路里点到名的文件才在工作"。**这是不对的。** 原因有两个：

### 误区来源①：程序其实分两个阶段，三条链路只是第二阶段

```
【阶段一：开机准备】(只在上电时跑一次，不属于任何链路)
   Init_All_Periph()  用到 → hw_config.c   (配主频时钟)
                              malloc.c      (初始化内存)
                              Gpio.c        (配引脚)
                              IO_operate.c  (配状态灯)
                              Comm_operate.c(打开串口)
                              RTC_operate.c (启动电子表)
                              flash_if.c    (读出保存的参数)
                              ADC_operate.c (电压相关)
                              sys.c         (底层辅助)
   Nvic.c (最后配好中断优先级，才允许中断发生)
        ↓ 准备完毕
【阶段二：运行循环 + 三条中断链路】← 第四节讲的就是这里
```
阶段一这一大批文件，开机时**全都用到了**，只是跑完一次就不再频繁露面，所以没出现在三条链路图里。

### 误区来源②：三条链路自己一路都在"借用"底层文件

链路不是孤立的，它们一边跑一边调用底层驱动。例如：

- **链路①（收指令）** 借用 → `Comm_operate.c`(组帧)、`PCLink_operate.c`(解析)、`flash_if.c`(存参数)、`FPGA_operate.c`(给FPGA下命令)
- **链路②（定时）** 借用 → `RTC_operate.c`(刷新时间)、`ms5837.c`(读深度)、`IO_operate.c`(切换灯色)、`date.c`/`calendar.c`(时间换算)
- **链路③（FPGA反馈）** 借用 → `FPGA_operate.c`

### 所以正确的结论

> **USER 文件夹里几乎所有 `.c` 文件都被用到了**——要么开机时用，要么被某条链路调用。
> 真正"没用到"的，**不是整个文件，而是文件内部被 `#if` 跳过的某些代码分支**（见下一节）。
>
> 换句话说：**裁剪发生在"文件内部的分支"层面，不是"整个文件"层面。**

## 六、哪些**代码分支**当前没用到？

回答你最初的问题——**"每行代码都有用吗？"答案是：不是。** 但要注意：没用到的是**文件内部的部分分支**，不是整个文件（见上一节）。

因为当前编译配置里关掉了一些功能开关（`USE_NET=0` 没接网口、`USE_FATFS=0` 没插SD卡、用内部时钟等），所以下面这些代码**在当前这台B型信标里完全不参与运行**（它们和有用的代码混在同一批文件里，靠 `#if` 在编译时被跳过）：

- **以太网/网络相关**（`ETH_*`、`Net_*`、lwIP 协议栈）——没接网线。
- **SD卡 / 文件系统**（`SD_*`、`f_open` 等 FatFs 函数）——没插SD卡。
- **外部时钟芯片**（DS1302 / DS3231）——用的是单片机内部的电子表。
- **其它型号设备的代码**：代码里大量 `iPosition_*`（定位器）、`iListen_*`（接收机）、`iLogger_*`（记录仪）、`iBeaconB2_*`、`iBeaconR_*` 的分支，都是**别的产品型号**的，当前型号(`iBeaconB`)把它们全部跳过了。

> 它们留着，是为了让**同一份源码**能编译出整个产品系列的不同设备。对你这台信标而言，大约一半的设备分支代码是"睡着的"，不影响运行，也不用管。

---

## 七、最后，一句话记住这台设备

> **它是一台装在沉管上的"水下精确发声器"。单片机当指挥、FPGA 当喇叭手：单片机通过 FMC 把发声参数交给 FPGA，FPGA 精确地发出微秒级声脉冲；设备靠 RTC/PPS 准时发声、用 MS5837 测自身深度、通过串口跟船上电脑通信。整个程序是"中断驱动"——主循环很闲，真正的活在串口中断、RTC中断、FPGA中断里完成。**
>
> 它只是整个沉管测控系统的**发射端**，定位算法在别处，不在这份固件里。
