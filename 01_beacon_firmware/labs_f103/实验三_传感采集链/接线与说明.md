# 实验三 · 传感采集链（ADC+DMA+滤波 与 软件I2C读MPU6050）

> 这是最接近信标固件"数据通路"的一个实验：
> - **模拟量链**：电位器 → ADC → DMA 自动搬进内存 → 滑动平均 → 转电压（对应 `ADC_operate.c`）
> - **数字量链**：MPU6050 → 软件 I2C 读寄存器 → 整数换算（对应 `ms5837.c`）

## 1. 复刻固件的什么

| 本实验 | 对应真固件 | 文件 |
|---|---|---|
| ADC 连续转换 + DMA 循环搬运 | `ADC_InitSingleDMA`（外设→内存、循环模式） | ADC_operate.c |
| DMA 缓冲区滑动平均 | `GetLiPowerVoltage` 的环形平均 | ADC_operate.c |
| 采样→滤波→标定 流水线 | 同上（除分压系数、限幅） | ADC_operate.c |
| 软件 I2C：Start/SendByte/**ReadByte/WaitAck** | `P_I2C_*` 系列 | ms5837.c |
| 写命令→重复起始→读多字节 | `MS583703BA_getConversion` | ms5837.c |
| 原始值×出厂系数→物理量 | `MS5837_Getdata` 温压公式 | ms5837.c |

> 实验一的 OLED 软件 I2C 是**只写**；这次 MPU6050 要**读**，所以多了 `WaitAck / ReadByte / Ack / NAck`——这才是完整的 I2C，和 `ms5837.c` 一模一样。

## 3. 接线

| 器件 | 引脚 | 接到开发板 |
|---|---|---|
| 电位器 | 两端 | 一端 3.3V、一端 GND |
| 电位器 | 中间脚(滑片) | **PA1** |
| MPU6050 | VCC | 3.3V |
| MPU6050 | GND | GND |
| MPU6050 | SCL | **PB8** |
| MPU6050 | SDA | **PB9** |
| MPU6050 | AD0 | GND（把地址定为 0x68，代码按这个写的） |
| OLED | VCC / GND | 3.3V / GND |
| OLED | SCL / SDA | **PB8 / PB9**（和 MPU6050 并联在同一条总线上！） |
| USB转TTL | RXD ← PA9，GND ← GND | 看打印（只需收方向；本实验不发命令） |

> MPU6050 模块上其它脚（XDA/XCL/INT）不用接。
> **OLED 和 MPU6050 共用 PB8/PB9 这一条 I2C 总线**——两个 SCL 接一起、两个 SDA 接一起即可。
> 这是个重要知识点：一条 I2C 总线靠"地址"区分多个设备（OLED=0x78、MPU6050=0xD0），互不干扰。
> 代码里 OLED 用自己的软件 I2C（oled.c）、MPU6050 用 main.c 的软件 I2C，都是 bit-bang 同两个脚，顺序执行不冲突。

## 4. 验收

串口助手 115200，上电后：
1. 先看到 `MPU6050 OK (WHO_AM_I=0x68)`——说明 I2C 读通了。
   - 若是 `NOT found (WHO_AM_I=0xFF/0x00)`：检查 SCL/SDA 有没有接反、AD0 是否接地、VCC 有没有电。
2. 之后每秒一行，例如：
   ```
   ADC: raw=2048  V=1650 mV  |  ACC(mg): x=-12 y=30 z=1001  |  GYR(0.1dps): x=2 y=-1 z=0  |  T=2680(0.01C)
   ```
3. **拧电位器** → `V` 在 0~3300mV 间变化（ADC+DMA 链通了）。
4. **平放模块** → `ACC z≈1000mg`（1个重力g）；**翻转/竖起** → 重力转移到 x 或 y 轴。
5. **转动模块** → `GYR` 对应轴跳出大数值，停下回到 ~0。
6. `T` 是芯片温度（约 室温+几度，单位 0.01℃，如 2680=26.8℃）。

**OLED 上同时显示**同一份数据（每秒刷新）：
```
ADC:1650 mV
AccZ: 1001 mg
GyrZ:     2
Temp: 2680 cC      (2680 = 26.80℃)
```

✅ 电压随旋钮变、加速度能感知重力方向、角速度能感知旋转、OLED 与串口数据一致 = 通过。你已经把"模拟+数字"两类传感器的完整采集链都跑通了，而且一条 I2C 总线同时带了 OLED 和 MPU6050 两个设备。

## 5. 做完想一想（答辩级）

- **DMA 的意义**：ADC 每秒转上万次，如果不用 DMA、靠 CPU 一个个 `ADC_GetConversionValue` 去搬，会怎样？DMA 循环模式下，CPU 在干嘛？（提示：CPU 全程没参与搬运，这就是为什么固件敢一边高速采集一边干别的）
- **为什么要平均**：直接取 `g_adcBuf[0]` 单个值和取 64 个平均，哪个稳？拧到中间不动时观察跳动幅度。
- **滑动 vs 双缓冲**：本实验 DMA 循环写、CPU 随时读同一个缓冲（可能读到正在被写的那格）。固件用"双缓冲乒乓"（一块写、一块算）避免这个问题——你能想到用 DMA 半传输+传输完成两个中断来模拟乒乓吗？
- **I2C 的"重复起始"**：`MPU_ReadBytes` 里为什么写完寄存器地址后要再来一次 `I2C_Start`（不先 Stop）？（提示：Stop 会让从机以为事务结束，地址指针就丢了）
- **开漏读线**：`SDA_READ()` 为什么能在"输出模式"下读到从机拉低的电平？（提示：开漏 + 释放=写1，线由谁拉低就读到谁）
