# 实验五 · 阵列信号处理入门：2元阵 TDOA 声源方向估计

> 这个实验和前面四个不是同一条线：不是复刻信标固件的某个模块，而是给你导师说的
> "阵列信号处理 + 硬件结合"搭一个能亲手摸到的最小实现。原理直接对应你毕设
> （短基线定位）接收端真正在做的事——多阵元测到达时间差(TDOA)反解方位角。

## 2. 接线表

| 功能 | 接到 |
|---|---|
| 麦克风A DO | **PA0** (EXTI0) |
| 麦克风A VCC / GND | 3.3V / GND |
| 麦克风B DO | **PA1** (EXTI1) |
| 麦克风B VCC / GND | 3.3V / GND |

| USB转TTL | TXD→PA10, RXD←PA9, GND（**3V3/5V不接**，板子已经USB供电） |

> 两个麦克风模块**务必是同一款、同一批**买的——型号不同灵敏度/响应速度不一致，会让测出来的Δt带系统性偏差，这属于阵列信号处理里"阵元失配"的坑，实验本身刚好也在验证这一点。

## 3. 摆放阵列

1. 把两个麦克风模块固定在直尺（或木条）两端，**中间隔一段已知距离 d**，建议 **15~20cm**：
   - d 太小：两个麦克风听到的时间差太小（几十微秒内），容易被阈值抖动淹没，测不准
   - d 太大：超出"远场平面波"假设的合理范围（声源离阵列不够远时，波前不是平面，公式会失真），也会让±90°附近（端射方向）的角度更难分辨
2. 拿尺子实测你摆的实际间距，改 `main.c` 里的：
   ```c
   #define ARRAY_D_MM   150     // 改成你实测的毫米数
   ```
3. 阵列摆好后垂直放在桌上，正前方（阵列的"中垂线"方向）留出至少50cm~1米的空间，方便测试不同角度。

## 4. 上电前先确认两个模块的"极性"

不同批次的声音传感器模块，DO脚在"没听到声音"时可能是低电平也可能是高电平，方向不一样代码要跟着改。main.c 默认按 **空闲低电平、听到声音跳高电平（上升沿触发）** 写的。

**验证方法**：程序烧录后打开串口，每秒会打印一行：
```
[HB] t=5s  triggerCount A=0 B=0
```
对着麦克风A**大声拍一下手**，如果 A 的计数没有跟着涨，大概率是这两种情况之一：
1. 接线本身有问题（参考前面实验里"列数要对齐"那些坑，重新核对）
2. **极性反了**——把 main.c 里 `Mic_EXTI_Init()` 里的：
   ```c
   gpio.GPIO_Mode = GPIO_Mode_IPD;        // 改成 GPIO_Mode_IPU
   exti.EXTI_Trigger = EXTI_Trigger_Rising;  // 改成 EXTI_Trigger_Falling
   ```
   改完重新烧录再测一次。

**两路都要分别验证**：拍手对着A，只看A的计数涨；拍手对着B，只看B的计数涨。两个都会涨了，再进行下一步。

> 大部分这类模块板上有个蓝色小电位器，是调**灵敏度阈值**的——如果一直不触发或者一直乱触发（环境噪声就误报），拿螺丝刀顺时针/逆时针轻轻转几下再试。

## 5. 怎么验证测向效果（验收标准）

两路都确认能正常触发之后，看主循环解算出来的方位角：

1. **正对阵列中垂线方向拍手/触发蜂鸣器**（离阵列正前方，左右居中）——串口应该打印类似：
   ```
   A_t=12345us B_t=12351us dt=6us  sinTheta=0.014  angle=0.8deg (偏向A侧)
   ```
   `angle` 应该**接近0**（±几度都算合理，别指望零误差）。

2. **明显偏向A那一侧发声**（比如站在A正前方，B那一侧斜后方）——`angle` 应该是**正值**，且提示"偏向A侧"。

3. **明显偏向B那一侧**——`angle` 应该是**负值**，提示"偏向B侧"。

4. **从A侧慢慢移动声源到B侧**（比如沿着阵列前方走一圈）——`angle` 的读数应该跟着**平滑地从正变负**（或反过来），趋势对就算通过，不需要读数精确到多少度。

如果方向感觉是反的（应该偏A却打印偏B），说明A、B两个模块的接线（PA0/PA1）接反了，或者你对"哪个是A哪个是B"的物理摆放和代码定义搞反了，交换一下接线或者交换代码里MIC_A_PIN/MIC_B_PIN对应的物理位置即可。

## 6. 误差来源（这是重点，写实验报告/ 跟导师讨论时用得上）

这个实验故意暴露了几个阵列信号处理里真实存在的问题，而不是回避它们：

1. **触发抖动（jitter）**：比较器阈值触发的时刻，跟"声音波形什么时候超过设定阈值"有关，不是一个稳定的物理参考点——声音大小、波形陡峭程度都会让触发时刻有几十微秒级的抖动。这是为什么用**阈值触发**测TDOA精度有限，真正的阵列信号处理系统（包括你毕设对应的短基线定位）会用**连续采样+互相关(cross-correlation)**去找Δt，能做到亚采样精度，比"阈值一触发就打时间戳"准得多。
2. **阵元失配**：两个麦克风模块灵敏度、响应延迟不完全一致，会给Δt带来一个固定偏差(bias)，反映到角度上就是"明明对准中垂线，角度却总是不为0"——如果你观察到这个现象，可以试着测量并记录这个固定偏差，这就是阵列标定(calibration)要解决的问题。
3. **声速受环境影响**：代码里 `SOUND_SPEED_MPS` 是固定的343m/s（约20℃），实际声速随温度变化（公式约 c=331.3+0.606×T，T是摄氏度）。如果想做得更"阵列信号处理"一点，可以拿实验三剩下的热敏传感器接回来，实时测温度算准确声速——这属于"环境参数对定位精度的影响"，也是短基线定位系统里的真实考量。
4. **端射区分辨率下降**：θ越接近±90°(阵列轴线方向，也就是"端射"方向)，sin(θ)对Δt的变化越不敏感（sin函数在±90°附近导数趋于0），同样的时间测量误差，换算成角度误差会明显变大——这是均匀线阵的经典特性，你在实验里把声源移到阵列两端附近测试时应该能感受到角度读数变得更"跳"、更不稳定。

## 7. 进阶方向（可选，不要求做，写出来是给你一个"往下走"的路标）

- **3元阵测完整2D方位角**：加第3个麦克风摆成L形（比如PA2/EXTI2），两条基线各解一个角度分量，合成完整平面方位角，而不只是"偏A还是偏B"这一维。
- **多基线定位（真正意义上的"短基线"）**：如果有3个以上阵元、知道它们的相对坐标，光测角度还不够，需要联立多组TDOA方程反解声源的**位置**（不只是方向），这才是完整的短基线定位数学，比这里的单一角度估计复杂一层。
- **真正的互相关测Δt**：把比较器阈值触发换成ADC+DMA连续采样两路麦克风的原始波形（参考实验三的ADC+DMA手法），离线对两段波形做互相关，找相关峰值对应的延迟，这是教科书里GCC-PHAT一类算法的简化版，精度比阈值触发高一个量级。

不需要都做，挑一个你觉得最能跟导师讲清楚"我做了什么"的方向深入即可。
