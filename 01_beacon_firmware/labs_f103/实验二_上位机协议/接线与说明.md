# 实验二 · 上位机协议（串口组帧 + 命令分发）

> 实验一你做出了"会心跳、会闪灯、能打印"的骨架。实验二让板子**听懂上位机的命令**——
> 这正是信标固件最核心的一条链：`USART中断 → 组帧 → 命令分发`。

## 1. 这个实验复刻固件的什么

| 本实验 | 对应真固件 | 文件 |
|---|---|---|
| `COMM_OBJECT` 结构体（打包一个串口的状态） | `COMM_OBJECT` | Comm_operate.h |
| `Comm_GetFrameMsg` 组帧状态机（$…*） | 同名函数，逻辑一模一样 | Comm_operate.c |
| `USART1_IRQHandler` 逐字节喂给组帧机 | `USART2_IRQHandler` | stm32f4xx_it.c |
| 命令分发大 `switch` | `OnEchoPCLINK` 的 switch | main.c |
| 地址=0 广播过滤 | `nAddr==0 || nAddr==g_stSys.nAddr` | main.c |
| 中断只置标志、后台处理 | 收齐帧置 `bRdy`，主循环 `OnEchoPCLINK` | 全局 |

**一句话**：你将亲手实现"下位机怎么听懂上位机说话"。

## 3. 接线（关键：这次要双向通串口！）

实验一你可能只接了"板子→电脑"看打印。实验二要给板子**发**命令，所以 USB转TTL 必须**双向**接：

| USB转TTL | 接到开发板 | 方向 |
|---|---|---|
| GND | G (GND) | 共地 |
| TXD | **PA10** (USART1 RX) | 电脑→板子（发命令，★实验一没接这根） |
| RXD | **PA9** (USART1 TX) | 板子→电脑（看回复） |

按键（可选，接 PA0↔GND）：按一下循环切 LED 模式 灭→常亮→闪。

## 4. 协议格式与命令表

格式：`$地址,命令号,参数1,参数2*`
- 地址 = 本机地址(默认 **1**) 才响应；地址 = **0** 是广播，所有设备都响应。

| 命令 | 格式 | 作用 | 板子回复示例 |
|---|---|---|---|
| 设闪烁周期 | `$1,1,周期ms,0*` | LED 改为闪，周期=参数1 | `$1,1,ok,blink=100ms*` |
| 查询状态 | `$1,2,0,0*` | 回 运行秒数/CPU/LED模式 | `$1,2,t=12s,cpu=2%,led=2,blink=500ms*` |
| 设 LED 模式 | `$1,3,模式,0*` | 模式：0灭 1常亮 2闪 | `$1,3,ok,led=1*` |
| 广播测试 | `$0,3,2,0*` | 地址0，本机也响应 | `$1,3,ok,led=2*` |
| 错误地址 | `$9,2,0,0*` | 地址≠1≠0，**不回复**（被过滤） | (无)|

## 5. 测试步骤

1. 串口助手设 **115200, 8N1**，打开端口。
2. 上电后每秒能看到心跳：`[HB] t=5s cpu=2% led=2 link=offline`
   （`link=offline` 是因为还没收到命令——这就是"通信即活性"的演示）
3. 发送框输入 `$1,2,0,0*` 发送 → 板子立刻回一行状态，且下一条心跳变成 `link=online`。
4. 发 `$1,1,100,0*` → LED 明显变快闪，回 `blink=100ms`。
5. 发 `$1,3,1,0*` → LED 常亮；`$1,3,2,0*` → 恢复闪。
6. 发 `$9,2,0,0*`（错误地址）→ **板子不理你**（地址过滤生效）。
7. 发 `$0,3,0,0*`（广播）→ 板子响应，LED 灭。

> 串口助手带不带"发送新行(\r\n)"都行——帧尾是 `*`，多余的换行会被状态机自动忽略。

✅ **验收**：能用命令改 LED、能查到状态、错误地址被忽略、广播能响应 = 通过。你已经实现了一个完整的下位机命令栈。

## 6. 做完想一想（答辩级）

- 为什么 USART 中断里只调 `Comm_GetFrameMsg`（喂字节），而把 `Comm_OnFrame`（解析+执行）放到主循环？如果把解析也塞进中断会怎样？（提示：中断要短；解析里有 `printf` 会阻塞）
- 组帧状态机为什么要先找 `$` 再开始存？如果上位机发到一半断了、或乱码先到，会不会把状态机搞乱？（试试只发 `1,2,0,0*` 不带 `$`）
- `g_linkIdle` 每秒+1、收到命令清0——这和真固件的"看门狗计数器"`uWatchDog` 是不是一回事？真设备靠它判断上位机掉线后做什么？
- 真固件一套代码管 6 个串口（`m_pComm1~6`），靠的就是 `COMM_OBJECT*` 传指针。你这里只有一个 `g_comm`，要扩成 2 个串口该怎么改？

## 7. 关于 IDE 里的红波浪线

VS Code 可能在 `#include "stm32f10x.h"` 下画红线、提示"无法打开源文件"——那是 **VS Code 的 IntelliSense** 不知道头文件路径，**不是 Keil 的编译错误**。Keil 有自己的 Include Paths，Build 完全不受影响，忽略即可。
