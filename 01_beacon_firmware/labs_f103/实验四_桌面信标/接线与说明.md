## 3. 器件与接线

| 器件 | 引脚 | 说明 |
|---|---|---|
| **无源蜂鸣器** | **PB1** | ⚠️见下方重要提醒 |
| 按键 | PA0 ↔ GND | 含义变了：这次按一下 = "模拟PPS，触发一次发射" |
| USB转TTL | TXD→PA10, RXD←PA9, GND | 双向（同实验二，需要收发命令）|

### ⚠️ 关于蜂鸣器：有源 vs 无源

你套件里如果是**有源蜂鸣器**（内部自带振荡电路），接上只会发出**固定音调**，听不出扫频变化——但发射的**时序、触发、看门狗**这些逻辑照样能验证：
- 发射期间 **LED 会同步快闪**（60ms一次），肉眼能确认"正在发射"和脉冲宽度节拍；
- 串口打印会显示 `EMIT start f1=800 f2=1600Hz width=300ms` → `EMIT done`，时间对得上。

想听到真正的扫频音调（低音滑向高音），需要一个**无源蜂鸣器**（无自带振荡电路，靠外部方波驱动，某宝/电子城约1元）。两种蜂鸣器接线完全一样（正负极），换上就能听出效果，不用改代码。

## 5. 测试步骤

**① 基本发射：**
1. 上电，串口(115200)看到 banner，含默认参数 `f1=800 f2=1600Hz width=300ms`
2. **按一下按键** → 听到蜂鸣器响一声（默认从800Hz滑到1600Hz，300ms），同时看到：
   ```
   >> KEY (simulate PPS)
   >> EMIT start f1=800 f2=1600Hz width=300ms
   >> EMIT done
   ```
3. 用命令 `$1,6,0,0*` 效果相同（用上位机代替按键触发）。

**② 改参数再测：**
1. 发 `$1,4,300,3000*` → 改成 300Hz→3000Hz 更明显的滑音
2. 发 `$1,5,800*` → 脉冲拉长到 800ms
3. 再按按键或发 `$1,6,0,0*`，听效果变化

**③ 参数掉电保存验证（重点）：**
1. 改好参数后发 `$1,7,0,0*` → 收到 `saved to flash`
2. **直接给板子断电重上电**（或按 RESET）
3. 上电 banner 里的 `f1/f2/width` 应该是你**刚才保存的值**，不是默认的 800/1600/300
   → 证明"关机不丢参数"生效了！这就是固件"USE_STMFLASH"的意义。
4. 也可以故意**不保存**、改个参数后直接断电重启，会发现又变回了上次保存的值（或默认值）——对比着测更有说服力。

**④ 看门狗演示（最直观的一个）：**
1. 发 `$1,9,0,0*`
2. 立刻收到 `hanging now (IWDG resets in ~3s)...`，然后**串口停止响应**（程序卡死在死循环里）
3. **约3秒后**，板子自动重启，串口重新打印开机 banner —— 全程你没动板子，是硬件看门狗自己把它救回来的
4. 这就是为什么水下信标"死机了也能自己恢复"，不需要人去按复位键。

✅ 全部四步都验证到 = 通过。你已经把"能发声、参数不丢、死了能自己活过来"这套工程级可靠性都亲手实现了一遍。

## 6. 做完想一想（答辩级）

- **为什么发射用定时器中断"手动翻转"而不是TIM的硬件PWM模式？** 提示：手动翻转更容易在每个周期临时改频率（扫频），如果用硬件PWM自动模式，改变频率需要动态改ARR/CCR，思路是一样的，只是这里选了更直白的教学写法。真实FPGA是硬件NCO，比这个更精确、更不占CPU。
- **`FreqDiv = 500000/f` 这个公式哪里来的？** 和PPT第12页写的 `FreqDiv = FPGA_CLOCK/(2·f)` 对比一下——FPGA_CLOCK=100MHz换成了我们TIM3的1MHz，本质是同一个公式。
- **为什么Flash要先"擦除整页"才能写？** 提示：Flash的物理特性是"只能把1改成0，不能把0改成1"，要恢复成1（可写状态）必须先擦除整页。这就是为什么不能像RAM一样随便改一个字节。
- **为什么参数结构体要有个 `magic` 校验字？** 提示：芯片出厂时Flash内容是全 `0xFF`，如果没有这个字段，第一次上电时会把"垃圾数据"当成有效参数加载进来。
- **`$1,9,0,0*` 死循环之后，为什么看门狗没有在死循环刚发生的瞬间就复位，而是等了3秒？** 这个"宽限期"是IWDG超时时间决定的——太短容易误触发（比如Flash擦除耗时几十毫秒），太长则死机后恢复慢，需要权衡。
- **按键的含义在实验二和实验四不一样**（切LED模式 → 模拟PPS触发发射）——为什么这么改？这是不是更贴近固件里"PPS触发信标发射"的真实语义？
