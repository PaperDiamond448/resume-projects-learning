# 灵犀 Mobile · 纯项目目录

这里仅包含灵犀 Mobile 的可运行项目本体：原生 Android 客户端、FastAPI 大脑适配层、移动端所需的 `lingxi` 核心、端侧模型资源、GUI-agent 技能数据，以及随源码维护的单元/冒烟测试。

不包含竞赛提交材料、研究数据与实验产物、真机取证、演示视频、APK 构建产物、IDE/Gradle 缓存、签名密钥、用户画像或本机工具安装包。

## 目录

```text
android/  Kotlin 客户端、端侧 KWS/ASR/MediaPipe 资源、arm64 原生库、JVM 单元测试
brain/    FastAPI 服务、GUI-agent 规划/视觉/反思、技能与记忆数据、冒烟测试
lingxi/   移动 Brain 所需的意图、融合、画像、应答和会话核心（最小依赖闭包）
configs/  无明文密钥的核心运行配置
data/     域路由小模型；不含数据集、用户画像或 PC 感知/TTS 大模型
deploy/   Cloud-1～5本地安全容器、凭据/隐私审计、Railway staging 与自管HTTPS备选
```

## 独立性边界

Brain 默认只加载本目录的 `lingxi/`、`configs/config.yaml` 和 `data/models/domain_router.pkl`，不再读取 `D:\华为比赛` 或其他 PC 项目源码。

仍需外部提供的只有正常运行环境：Python/Android工具链、中国区Qwen3-14B Key、天气/地图Key，以及在需要GUI视觉时在线的自托管精确Qwen2.5-VL-3B-Instruct节点。Key只通过环境变量或运行时secret提供，不能写进项目；文本Key不得被视觉链复用。

## 启动 Brain

```powershell
$env:NO_PROXY='*'
$env:LINGXI_VLM_BASE_URL='http://<VLM主机IP>:1234/v1'
$env:LINGXI_VLM_MODEL='qwen2.5-vl-3b-instruct'
$env:LINGXI_VLM_API_KEY='local'
$env:LINGXI_VLM_TIMEOUT='30'
D:/python/python.exe brain/server.py --host 0.0.0.0 --port 8000
```

独立性基础冒烟（离线，不调用 14B/VLM）：

```powershell
D:/python/python.exe -B brain/smoke_standalone.py
```

`brain/smoke_server.py` 是包含真实 14B 调用和历史行为断言的扩展回归，需有效 Key 与网络；它不作为“源码是否独立”的基础判据。

高风险短信/电话待确认的冻结规则与独立审计见 `SAFETY_CONTRACT.md`、`B08_REGRESSION_REPORT.md`。契约审计不调用真实模型：

```powershell
D:/python/python.exe -B brain/audit_pending_contract.py
```

## Cloud-1/2/3 本地安全容器

Cloud-1已完成可重复容器化；Cloud-2已增加设备Bearer、主体绑定、持久`request_id`幂等、请求限制、最小liveness/readiness、日志脱敏和secure-local启动门。最终镜像以非root、单worker、只读根运行且只绑定`127.0.0.1:8000`；构建阶段通过pending 29/29、standalone、Cloud-2单元7/7和安全审计18/18，运行镜像不含Android源码、缓存、本机路径或业务密钥。

Cloud-3新增独立云截图同意、用途/敏感度/SHA证据和Android/Brain双门；敏感页在手机本地硬停，天气不再按服务器IP猜城市，VLM只接受精确`qwen2.5-vl-3b-instruct`且没有第三方替身回退。用户原有台式机LM Studio自托管链此前已跑通；当前只是3B机器不在身边，故默认关闭视觉并让其他能力独立运行。Cloud-3单测10/10、离线审计15/15、自托管地址策略6/6、部署预检26/26已通过。

Android endpoint现可手动配置，Bearer由Android Keystore AES-GCM保护；debug HTTP仅允许本机/模拟器回环，release代码和平台策略均只接受HTTPS。Cloud-5采用Railway托管容器并保留Debug APK＋USB本地Brain路径。首轮公网性能反证后，本副本加入严格当前天气/时间路由、4秒总墙钟硬截止、天气3.5秒截止/成功缓存和安全纯聊天紧凑单轮。UTC报时失败又推动显式`LINGXI_TIMEZONE=Asia/Shanghai`转换；18/18延迟契约、36/36预检、17/17入口及Cloud-2/3/4门均通过。无缓存镜像`sha256:e8ea9197...390ee`和Railway部署`608e2211...f66b`通过，公网报时误差0分钟、wall=`1.265s`、零动作。拔USB同一Release现场通过天气、正确`11:37`报时和两句内冷笑话，证明App有互联网时不依赖ADB或PC Brain进程。蜂窝因设备无流量按用户决定未测试；本轮Wi-Fi来自Windows热点，也不证明电脑关机后的网络独立，故仍称VLM-disabled staging而非production。VLM-disabled与精确3B型号边界不变。具体步骤见`deploy/cloud/RAILWAY.md`。

r2 矩阵后只在本目录追加 KWS 请求状态/真实 Service 生命周期同步修复；r3 真机显示与服务状态一致。该补丁不改 KWS/ASR 模型、确认阈值或 Brain 安全状态机。

旧 `smoke_server.py` 原样保留历史断言，其中“pending 内原地修改收件人/正文”和“旧客户端不带来源即可确认执行”已不再代表当前安全契约，不以修改旧断言的方式制造全绿。

## 构建 Android

项目使用 Android Gradle Plugin 8.5.2、Kotlin 1.9.24、Gradle 8.9、JDK 17 与 compileSdk 34。本机现有工具链示例：

```powershell
$env:JAVA_HOME='D:/Android/jbr'
$env:GRADLE_USER_HOME='D:/AndroidDev/gradle-home'
D:/AndroidDev/gradle-home/wrapper/dists/gradle-8.9-bin/90cnw93cvbtalezasaz0blq0a/gradle-8.9/bin/gradle.bat -p android assembleDebug
```

真机通过 USB 访问电脑 Brain 时：

```powershell
D:/AndroidDev/Sdk/platform-tools/adb.exe -s 2687da22 reverse tcp:8000 tcp:8000
```

更详细的模块说明见 `android/README.md` 与 `brain/README.md`。
