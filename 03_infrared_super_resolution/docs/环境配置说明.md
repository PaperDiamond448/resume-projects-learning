# 环境配置说明

## 一、硬件要求

训练阶段我们实际使用的是单张 NVIDIA A10（24GB 显存）。最终方案的模型仅 0.87M 参数，显存占用不高，在训练块 96、批大小 16 的配置下即可正常训练，一次完整训练（150 个 epoch）约需 3 小时。

推理阶段对硬件要求很低。代码会自动检测 CUDA 是否可用，在没有 GPU 的机器上会自动回退到 CPU 运行。我们已在纯 CPU 环境下完成过完整的复现验证。

## 二、软件环境

项目基于 Python 3.10 与 PyTorch 2.x 开发，Linux 与 Windows 均可运行。安装依赖只需执行：

```bash
pip install -r requirements.txt
```

主要依赖为 PyTorch、torchvision、NumPy、Pillow，以及 HiT-SR 系列骨干所需的 timm；本地按官方指标打分时会额外用到 lpips。

### 关于 basicsr 与 huggingface_hub

HiT-SR 的官方架构文件（`src/hit_srf_arch.py`、`src/hit_sir_arch.py`）在文件顶部引用了 `basicsr.utils.registry` 的模型注册器与 `huggingface_hub` 的 `PyTorchModelHubMixin`。这两者仅用于其原始训练框架的模型登记与模型库上传，与网络的数值计算完全无关。

为了避免为此引入两个较重的依赖，我们在 `src/_compat_shims.py` 中提供了一份零依赖的兼容实现：当这两个库缺失时，自动注入一个空的注册装饰器与一个空的 Mixin 基类；若运行环境中已安装官方库，则优先使用官方库，兼容实现自动失效。因此**本项目无需安装 basicsr 与 huggingface_hub，在完全离线的环境中也可以直接运行**。

同一份兼容实现还处理了 timm 的版本差异：部分官方架构使用 `from timm.layers import ...`，而较旧版本的 timm 只提供 `timm.models.layers`；缺失时会自动做模块别名，从而保证代码在新旧 timm 上都能导入。

### 关于 PyTorch 版本兼容

赛题给出的评测环境参考为 PyTorch 1.9 及以上。需要注意的是，`torch.load` 的 `weights_only` 参数在 PyTorch 1.13 之前并不存在，而在 2.6 及以后其默认值又变为 `True`（会拒绝加载包含配置字典的检查点）。为了让同一份代码在跨度如此大的版本区间内都能正常加载权重，我们在 `src/ckpt_utils.py` 中实现了 `robust_load`：优先按新版本的方式显式传入该参数，若当前版本不识别则自动回退到旧版本的调用方式。推理入口 `src/infer.py` 统一使用该函数加载权重。

## 三、预训练权重的获取

最终方案以官方 HiT-SRF 的 4 倍预训练权重为起点。我们使用的是其在 **DF2K**（DIV2K + Flickr2K，约 3450 张）上训练的版本，相比 DIV2K 的 800 张，预训练数据更多、先验更强。

- 项目地址：https://github.com/XiangZ-0/HiT-SR
- 预训练权重：由该项目的 OneDrive 模型库提供，取其中 HiT-SRF 的 4 倍（DF2K）权重，我们本地重命名为 `HiT-SRF-4x-DF2K.pth`。

需要说明的是，该预训练权重是在**标准双三次降质**的自然图像上训练的，与本赛题官方的降质方式一致（我们在第一阶段已还原确认官方降质即为双三次抗锯齿下采样加 8 比特量化，第二阶段的 4 倍降质也做了同样的复验）。正因如此，它才能作为与本任务高度对齐的先验。

**复现推理不需要下载这份预训练权重**——`weights/model.pth` 已经是微调完成的最终模型。只有在需要从头复现训练时才需要它。

## 四、训练注意事项

以下几点是我们在实际训练中付出代价换来的经验，一并记录。

**训练块尺寸受输入分辨率限制。** 4 倍任务的低清输入只有 160×128，训练块（patch）无法像 2 倍任务那样取到 128。我们选择 96：既能给窗口注意力足够的上下文，又能在裁剪位置上保留随机性。若取到 128，纵向将没有任何裁剪余量。

**批大小变化时，学习率必须同比缩放。** 这是第一阶段留下的教训：当时在 24GB 显存下训练 HAT-L，被迫将批大小由 4 降到 2 却没有调整学习率，结果训练精度长时间停滞、反复波动；将学习率同步减半后训练立即恢复正常。第二阶段的模型很小，未再遇到这一问题，但配置仍需遵守这一原则。

**判断模型「是否在学」，要看训练损失是否下降，而不是反复调学习率。** 我们在轻量模型上曾观察到验证精度长期不涨，最初误判为学习率过高，将其调低后依然不涨；后来注意到训练损失从头到尾都没有下降，才意识到这是模型容量与任务信息上限造成的收敛，而非优化问题。这一判据帮助我们避免了在学习率上做无意义的反复尝试。

**低精度存储的兼容性必须提前验证。** 赛题强制权重以 FP16 及更低精度存储。我们在评估候选骨干时发现，含离散路由结构的网络（如 ATD）对权重量化异常敏感——单看每个权重张量的 FP16 量化误差都只有万分之五，看似毫无问题，但在真实图像上，量化前后模型输出的差异会被放大到 40~48 dB（其它模型约 80 dB）。因此在这类任务中，选型时必须在**真实数据**上测量「量化前后输出的差异」，而不能只看全精度下的基准分数。
