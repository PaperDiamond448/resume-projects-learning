**做了什么**

1. **读透全部赛事材料**，确认第二阶段规则相对一阶段是「根本反转」（参数量/体积进评分 + 人工分 40%）。建 `第二阶段/` 文件夹 + `第二阶段作战规划.md`（战略）。
2. **加 SwinIR 变体支持**（`src/model_swinir_pretrained.py`）：GraySwinIR 现支持 `config['swinir_variant']`：
   - `classical`（默认，一阶段 ×2 主力）= SwinIR-M，embed180/depths[6]×6/`pixelshuffle`，~12M。
   - `light`（★二阶段主力）= SwinIR-S，embed60/depths[6]×4/`pixelshuffledirect`，~0.9M。
   - 放大倍数取自 `config['scale']`（一阶段=2，二阶段=4）。旧 ckpt 无该键 → 默认 classical（向后兼容）。
3. **train.py 加 `--swinir_variant {classical,light}`**，并把它写进保存的 config（infer 据此重建）。
4. **体积优化（关系评分「体积 15 分」）**：新增 `src/ckpt_utils.py`：
   - `strip_deterministic_buffers()`：提交存盘时剥掉 `attn_mask` / `relative_position_index`（确定性 buffer，加载时由 `__init__` 重建，真实推理分辨率下还会动态重算，存盘那份用不到）。
   - `load_params()`：加载用 `strict=False` 容许这些 buffer 缺失，但**断言所有可学习参数齐全**（保留 strict 的检错能力）。
   - 三处加载点统一改用 `load_params`：`infer.load_model` / `infer_ensemble.load_model` / `train.py --finetune`。
   - `train.save_best_model` 改为存盘前剥离 + `.half()`。
5. **写验证脚本** `第二阶段/smoke_test_4x.py`（一键全绿）。

**实测结果（CPU smoke 全过）**

| 验证项 | 结果 |
|--------|------|
| SwinIR-S **light 4×** 前向 128×160→512×640 | ✅ |
| light 参数量 / FP16 体积 | **0.930M / 1.77MB** |
| SwinIR-M **classical 4×**（质量参照）| 11.90M |
| dataset scale=4：LR patch 32→HR patch 128 | ✅ |
| TTA×8 推理输出 640×512 | ✅ |
| **提交权重瘦身：8MB → 1.86MB（4.3×）** | ✅ |
| 瘦身后 infer 重建前向一致 | ✅ max\|Δ\|=3.8e-4（仅 FP16 往返误差）|

| 旧一阶段权重（含完整 buffer）经新 `load_params` 加载 | ✅ 向后兼容 |

**经验 / 教训**

- 💡 **体积分是「免费午餐」**：轻量模型参数 FP16 才 1.77MB，但 naive 存盘是 8MB——6MB 全是确定性 buffer。剥掉直接拿满体积分，零数值代价。**第二阶段任何 transformer SR 模型都该这么存。**
- 💡 **改 strict→strict=False 一定要配「可学习参数齐全」断言**，否则会把"真权重缺失/架构不匹配"这类 bug 静默放过（一阶段 Run 10b 就吃过"--finetune 路径错被静默跳过、从零训练"的亏）。
- 💡 **dataset / infer 的 scale 是通用的**（HR crop = LR×scale；infer 输出强制 640×512），从 ×2 到 ×4 无需改这两个文件，只需训练/推理传对 scale 与 `--lr_folder input_160`。
- 改动隔离得很干净：核心只动 2 个模型/训练文件 + 1 个新工具文件，回归测试覆盖了向后兼容。

**产出文件**：`src/ckpt_utils.py`（新）、`src/model_swinir_pretrained.py`（改）、`src/train.py`（改）、`src/infer.py`（改）、`src/infer_ensemble.py`（改）、`第二阶段/smoke_test_4x.py`（新）、`第二阶段/第二阶段作战规划.md`（新）。

- **✅ 自检通过（2026-06-20）**：`[GraySwinIR/light]` **匹配 366 张量，missing=0 unexpected=0**（官方 light×4 与架构完美对齐）；4× 前向 (1,1,128,160)→(1,1,512,640)；0.930M/1.77MB；A10 GPU 前向 OK。
- **Run L1 配置**：`--swinir_variant light --scale 4 --pretrained 002_lightweightSR…x4 --patch_size 64 --batch_size 16 --epochs 150 --lr 2e-4→1e-6 cosine --amp bf16 --ema 0.999 --val_ratio 0.05`，save_dir=`checkpoints_light_x4`，~25.5s/epoch。

#### ❌ Run L1 失败（lr 2e-4 太高，模型没学进去）

| epoch | raw PSNR | EMA PSNR | train_loss |
|-------|----------|----------|------------|
| 10 | 27.2127 | 27.2591 | 0.02664 |
| 20 | 27.2264 | 27.2787 | 0.02617 |
| 30 | 27.2210 | 27.2900 | 0.02661 |
| 40 | 27.2211 | 27.3043 | 0.02598 |
| 50 | 27.2451 | 27.3147 | 0.02648 |

- **现象**：50ep val PSNR 仅 +0.05dB，**train_loss 全程平在 0.026 不降**，raw 横在 27.2、EMA 略高且缓爬、raw<EMA。
- **诊断**：复现第一阶段 **Run 15 HAT-L 失败模式**——LR 太高对强预训练先验扰动过大，descend 不进更优点。light 仅 0.9M（比 SwinIR-M 11.75M 小一个量级），loss 面更尖锐，`lr 2e-4`（一阶段 SwinIR-M ×2 能用）对它过冲。
- 💡 **教训**：**预训练骨干越小，微调 LR 要越保守**；判断"是否在学"看 train_loss 是否下降 + raw 是否追上/超过 EMA（raw 长期低于 EMA = 在抖、没 descend）。

#### Run L2：lr 2e-4 → **5e-5** → ❌ 仍平（推翻"LR 太高"诊断）

- bicubic×4 基线（90 val）：**PSNR 24.9231 / SSIM 0.8076**。
- Run L2 (lr5e-5)：ep5 27.19 / ep10 27.21，**train_loss 仍平在 0.0266**，与 lr2e-4 完全一样。
- **⚠️ 推翻上一诊断**：两个 LR 都卡 27.2 → **不是 LR 问题**。

#### 🔑 真因：light(0.9M) 撞容量天花板（非 bug、非 LR）

- light 输出 27.2 dB = bicubic 24.92 **+2.3 dB**，是实打实超分 → 管线正常。
- 但**几乎不随训练提升**（任何 LR）。机理：**官方 light×4 在"干净 bicubic×4"上预训练，与本赛题降质同一任务**；×4 超分主要靠通用上采样（弱依赖红外/可见光内容），红外微调能加的 PSNR 极少。0.9M 容量在 ×4 已榨干，撞顶 27.2。
- 对比一阶段 ×2：×2 简单、小模型有余量适配红外→微调有效；×4 难，小模型无余量。
- 💡 **教训**：①判断"是否在学"看 **train_loss 是否下降**（这里两个 LR 都不降=已到容量/任务上限，不是优化问题）；②**与赛题同降质的预训练越强，小模型微调余量越小**——×4 想要质量必须给容量。
- **light 帕累托候选保留**：`checkpoints_light_x4/best_model_ema.pth`（EMA 27.31，最省体积 1.88MB）。+2.3dB 对 ×4 偏低（好模型 +3~4.5），quality 竞争力不足。

#### Run C1（进行中）：classical ×4（SwinIR-M 12M）测质量天花板

- 配置：`--swinir_variant classical --scale 4 --pretrained 001_classicalSR_DF2K…x4 --patch_size 64 --batch_size 8 --lr 2e-4→1e-6 --amp bf16 --ema --val_every 5`，save_dir=`checkpoints_cls_x4`。
- 双重目的：①测 ×4 质量上限定帕累托点；②不同模型同 ×4 路径 → 若 classical 能爬则证明管线无 ×4 bug、light 纯属容量不足。
- 判据：起始 val 应高于 light；train_loss 应下降、val 持续爬过 28+。

|-------|----------|----------|----------|---------|
| 5  | 27.5046 | 27.5522 | 0.8832 | 77.2 |
| 10 | 27.5232 | 27.5789 | 0.8838 | 77.3 |

#### 🎯 策略判断（基于 ×4 低天花板）

- **待定**：让 classical patch64 跑到 ep30/50 看真实顶；之后视情况上 **patch128 杠杆**（一阶段 patch64→128 给 SwinIR +0.3~1.0dB，×4 更吃上下文）冲质量锚。最终按帕累托（质量↔体积）选主力，大概率 light 或某个中间档。
